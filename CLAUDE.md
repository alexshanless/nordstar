# NordStar Freight — project rules

Marketing site for NordStar Freight. `PLAN.md` is the working plan: read it
before starting work, check items off as they land, keep it current. Design
system docs live in `design/readme.md`.

## Stack

Next.js 16 App Router (Turbopack), React 19, TypeScript strict, Tailwind v4.
Static prerender everywhere: every route must stay static, no runtime servers
beyond server actions. `npm run build` must be green before any work is
called done.

## Design system (hard rules)

- Tokens only. Every color, font, space, radius, shadow comes from the CSS
  variables in `src/styles/industry.css`. Never hard-code a hex, font name,
  or px value the tokens carry. Dark-band overrides live in
  `src/styles/nordstar.css` — the site is dark-theme only.
- Blueprint grammar: cards, figures, and primary buttons are square-cornered,
  hairline-bordered, with four corner registration marks. Use the
  `Blueprint` component (`src/components/Blueprint.tsx`), never hand-write
  the corner `<i>` fragment. Cards and figures stay transparent line
  drawings; the solid steel primary button is the only filled object.
- Dark ground: interactive states step LIGHTER (accent-400/500). Small
  accent text uses `--color-accent-400`.
- Logo (`src/components/Logo.tsx`, assets in `public/brand/`): never scale
  the two-line lockup below a 40px mark — swap variants instead. No
  animation on the mark, ever. Never screen the logo back with opacity.
- Photography goes through `.duotone`. Icons are Lucide at stroke-width 1.5.
- Do not fork or casually edit `industry.css`; it is the imported design
  system. Brand-specific changes go in `nordstar.css`.

## Copy and content

- Voice: plain, concrete, engineering-document tone. No hype, no
  superlatives, no em-dashes as punctuation.
- Real marketing copy, compliance numbers (MC/USDOT), job/pay facts, and
  imagery are product inputs from Alex. Do not invent them as final —
  placeholder prose must read as plausible but is flagged in PLAN.md's open
  questions, not silently made up.

## Conventions

- No backend, all mock data (Alex's decision, 2026-08-07). Forms deliver
  via mailto: client-side Zod validation from the shared schemas in
  `src/lib/forms.ts`, valid submit composes a prefilled mailto, and each
  form shows a plain mailto fallback link (the no-JS path). No server
  actions, no email provider, no database.
- Errors and success states styled from tokens, never browser defaults;
  error color is the steel ramp (`--color-accent-300`), never red.
- Content as typed data in `src/content/` (e.g. `jobs.ts`) before reaching
  for MDX or a CMS.
- Destination inboxes (quotes@ / careers@nordstarfreight.com) are invented
  placeholders pending Alex's confirmation.
- AGENTS.md is auto-generated by `next dev` — do not edit it, and read the
  bundled docs in `node_modules/next/dist/docs/` before using Next.js APIs
  that may have changed.
